# WoZ 實驗系統

參與者看的食譜畫面（client）＋ 實驗者操控的控制台（wizard），兩邊透過一個 Python server 即時同步。

## 啟動

```sh
python3 server/serve.py
```

只用 Python 標準函式庫，不需要安裝任何套件。啟動後會印出兩組網址：

```
本機      http://localhost:8000
區網      http://192.168.x.x:8000
參與者    http://localhost:8000/client/
Wizard    http://localhost:8000/wizard/
```

開 `http://localhost:8000` 會看到啟動頁，兩個連結分別進入參與者畫面與控制台。

- **同一台電腦**：開兩個瀏覽器視窗，一個放參與者畫面（拖到外接螢幕後按「全螢幕」），一個放控制台。
- **兩台電腦**：另一台連區網網址（例如 `http://192.168.0.12:8000/client/`），兩台要在同一個區域網路下。程式碼路徑完全相同，不用改任何設定。

其他選項：`--port 8000`、`--host 0.0.0.0`（預設綁全部介面，跨機才連得到）。

> 必須透過這個 server 開啟，不能用 `file://` 直接開 HTML。

## 目錄結構

```
server/serve.py     靜態檔案 + /api 狀態中繼（SSE 推送 / POST 動作）
server/state.py     預設狀態與 reducer —— 所有規則只在這裡實作一次
shared/store.js     前端連線層：訂閱狀態、送出動作
shared/format.js    兩邊共用的格式化工具
client/             參與者畫面
wizard/             Wizard 控制台
data/               Excel 與產生出來的 recipe-data.js
sessions/           每次啟動自動產生的操作紀錄（JSONL）
scripts/            Excel → recipe-data.js 的轉換腳本
```

**狀態放在 server，兩個 UI 都只送「動作」**。任何一邊按下按鈕，送出的是意圖（例如「把 0:1 標成接受幫助、花費 3 點」），server 套用規則、算出新狀態，再推播給所有連著的畫面。因此兩邊不可能不同步，重新整理也不會掉狀態。

## Wizard 控制台

### 上方：頁面切換
每一頁一顆數字按鈕，直接跳頁，或用左右箭頭。右上角小圓點代表那一頁已經有勾選紀錄。右側顯示目前的「餐點 · 階段」與連線狀態。

### 左下：本頁步驟
每個步驟兩個勾選框：

- **完成** —— 參與者畫面上該步驟轉成灰階（代表參與者已經做完，不用再看）。**不影響點數。**
- **1. 被動等待－實體／語音** —— 兩顆按鈕分別以琥珀色、紫色呈現。按下後參與者畫面會浮出原本的整頁說明卡，標題依模式顯示「實體介入」或「語音介入」，並依旁邊「花費」扣點。兩種模式互斥，切換模式不會重複扣點。

「本頁全部完成 / 本頁全部取消」可以一次處理整頁。

**「▶ 預覽全部步驟」**：參與者畫面會從本頁第一個步驟開始逐一預覽；左側圖片與詳細動作同步切換，右側列表自動往下捲、上方最多保留兩個看過的步驟。播放中按鈕會變成「■ 停止預覽」，再按一次就立即停止。看過的步驟在預覽期間會變灰，停止或播放完成後回到編號最小的未完成步驟，不會改動完成紀錄或點數。每步停留時間由 `client/client.js` 的 `PREVIEW_STEP_MS` 調整（毫秒）；大型提示框的寬度、高度與字級則由 `client/client.css` 的 `--preview-popup-width`、`--preview-popup-height`、`--preview-popup-font-size` 調整。

#### 詳細步驟與計價
每個步驟底下的「詳細步驟 N / N」展開後，是這個步驟在 Excel 上的分解動作，**預設全部勾選**。這份勾選同時決定兩件事：

- 參與者說明卡上哪幾條是黑的 —— 說明卡**永遠列出全部的動作**，勾起來的是黑字（助手會做），**沒勾的變成淺灰色**（參與者自己做）。
- 花費多少點 —— **全部勾選＝Excel 原價；少勾幾個＝剩下勾選的個數**（目前資料裡每個步驟的原價都剛好等於詳細步驟的個數，所以兩條規則是同一條）。

選擇任一被動介入模式時，該步驟會自動展開，方便馬上調整。已經扣過點之後再改詳細步驟也可以，**帳本上那一筆會就地改成新的金額，不會多記一筆**。

「花費」欄位平常跟著詳細步驟自動算；如果你手動打了數字，就以你打的為準，直到你再動一次詳細步驟為止（那時會交還給自動計價）。要記任意金額也可以用右側的「手動調整」。

#### 說明卡的開關
每個步驟右邊的「顯示說明卡 / 隱藏說明卡」控制參與者畫面上那張整頁的框。選擇「實體」或「語音」時會自動叫出來，勾「完成」時會自動收掉。重新顯示時會保留所選模式的標題。說明卡屬於哪一頁的步驟都沒關係 —— 只要有卡在顯示，步驟清單上方就會出現一條提示列，上面的「關閉說明卡」隨時關得掉。

**指定 Client 查看步驟**：用「↑ 查看上一個／↓ 查看下一個」逐步移動，或按任一步驟列裡的「在 Client 顯示」直接指定。Client 右側會捲到該步驟、左側同步顯示圖片與詳細動作；Wizard 會顯示「Client 正在查看」提示並標出對應列。按「回到目前步驟」即可退出，回到編號最小的未完成步驟。這只是暫時查看，不會把步驟標成完成，也不影響點數；指定查看時若正在自動預覽，預覽會停止。

### 右下：點數
總預算（`server/state.py` 的 `TOTAL_BUDGET`，預設 **278**）拆成**兩個各自獨立的池**：

| 池 | 來源 | 總額 |
|---|---|---|
| **可指揮助手** | 參與者主動要求，控制台選「1. 被動等待－實體／語音」 | `TOTAL_BUDGET − 主動幫助池`＝目前 **200** |
| **主動幫助** | 助手主動提議，參與者可以不接受 | 由 Excel「介入」欄自動算出＝目前 **78** |

主動幫助池的總額不是常數，改 Excel 的「介入」欄再重跑 `scripts/extract_recipe.py` 就會變，**可指揮助手池會自動跟著調整**，兩池相加永遠等於 `TOTAL_BUDGET`。

- Wizard 不另外顯示合計總點數；合計總預算 **278** 仍會保存在狀態與輸出檔。要修改請調整 `server/state.py` 的 `TOTAL_BUDGET`。
- **剩餘可指揮助手點數**：左格以「剩餘 / 總額」顯示，例如 `200 / 200`。剩餘值永遠等於這一池總額加上本池所有帳目的總和，負數會顯示成紅色。
- **剩餘主動幫助點數**：顯示成「剩餘 / 總額」。總額不是常數，是掃過 Excel 的「介入」欄算出來的（見〈助手主動提議〉）。
- **手動調整**：輸入數字後按「＋ 加點」或「－ 扣點」（按 Enter 等於扣點）。
- **紀錄**：依頁數、步驟與介入模式由上往下排序，最左側顯示頁碼，模式分成「1. 被動／3. 主動」。畫面不顯示 timestamp，但資料中仍完整保留；若只選部分詳細動作，該列會顯示「有選／未選」banner。
- **輸出紀錄**：下載一份 JSON，包含總預算、兩池點數、依頁面與步驟排序的被動／主動介入紀錄、接受狀態、點數變化、完整 timestamp，以及每個步驟有選與未選的詳細動作。
- **回溯最後操作**：畫面雖按頁面排序，這顆仍會撤銷時間上最後一次帳目操作；可以連續按。如果撤銷的是被動幫助，參與者畫面上對應的標記也會跟著消失。
- **重置全部**：清空頁面、勾選與所有點數紀錄，換受試者時用。

### 帳本的規則
帳本是「目前生效的帳目清單」，不是唯讀的歷史日誌 —— **取消勾選「接受幫助」時，那一筆帳目會直接消失、點數自動回補**，而不是再記一筆反向帳。同理，**改詳細步驟是就地改掉那一筆的金額**，不會多一筆。這樣「剩餘點數」與畫面上的勾選狀態不可能脫鉤，回溯的結果也永遠可預期。

沒有全勾詳細動作的帳目，紀錄列下方會出現 banner，分別列出哪些動作「有選」、哪些「未選」。

「不接受」的主動提議在底層帳本仍包含主動扣點與可指揮退點兩筆，但 Wizard 會合併成一列同時顯示兩個點數變化。回溯時兩筆會一起消失，兩個池同時復原。

完整、不可竄改的操作歷程另外記在 `sessions/session-YYYYMMDD-HHMMSS.jsonl`，每個動作一行。每行除了原本的 action、版本與餘額，也包含當下完整 `state` 及已整理的 `records`，所以 timestamp、點數帳本、完成狀態、詳細動作選取、被動指揮與主動幫助都能還原。

## 助手主動提議

除了參與者自己要求的「助手介入」之外，助手還可以**主動提議**幫忙。提議的範圍不是控制台勾出來的，而是寫在 Excel 的 **M 欄「介入」**：值是 `O` 的那一列，代表該條詳細動作屬於主動提議的範圍。目前共 78 個 `O`，落在 **14 個步驟、13 個頁面**上。

### 計價
與「接受幫助」同一條規則：**整個步驟的詳細動作都標 `O` ＝ Excel 原價；只標幾條 ＝ 標到的條數**。14 個步驟加總起來剛好等於 `O` 的總數 78，也就是主動幫助池的總額 —— 全部提議都被用掉時剛好歸零。

重跑 `scripts/extract_recipe.py` 時會印出一張表，列出哪些步驟有標記、各標了幾條、花費多少，最後一行是合計。**這個合計就是主動幫助池的總額**，改完 Excel 一眼就能確認。

### 控制台的操作
只有標過 `O` 的步驟，底下才會在兩顆「1. 被動等待」按鈕上方多一列（其餘步驟完全不變）：

```
[✓] 3. 詢問後實體介入 4/8   花費 [4] 點   [接受] [不接受] [取消]
-------------------------------------------------------------
[1. 被動等待 - 實體] [1. 被動等待 - 語音]   花費 [8] 點   [顯示說明卡]
    詳細動作 8/8
```

- **「3. 詢問後實體介入」藍色色塊** —— 點擊時把提議卡推到參與者畫面上、整個步驟換成藍色底，再按一次收起。它取代原本的「顯示提議卡」按鈕；兩顆「1. 被動等待」則分別使用琥珀色（實體）與紫色（語音）。提議卡與說明卡**互斥**，畫面上同時只會有一張。
- **接受 / 不接受** —— 參與者口頭回答，由控制台代按：
  - **接受** → 主動幫助池扣掉花費，可指揮助手池不動。
  - **不接受** → 主動幫助池**一樣**扣掉花費，但**等額退進可指揮助手池** —— 參與者不接受主動幫助時，等於把那筆額度轉成自己能支配的資源。
- **取消** —— 把這個步驟的回答與帳目整組拿掉，回到還沒回答的狀態。

回答之後花費欄位會鎖住，要改金額先按「取消」。「詳細動作」清單裡屬於主動提議範圍的那幾條，編號前面會有一個**藍點**，方便實驗中確認範圍。

主動提議與「助手介入」**各自獨立**：同一個步驟兩者都可以用（例如參與者拒絕了主動提議，之後又自己用可指揮點數要求同一個步驟的幫助），帳目分開記在各自的池裡。

### 參與者畫面上的提議卡
與說明卡是同一塊版面，只換色系（**藍色**，說明卡是琥珀色）與文字，所以參與者不會搞混：

| | 說明卡 | 提議卡 |
|---|---|---|
| 眉標 | 🤖 助手介入 | 🤖 助手主動提議 |
| 黑字的來源 | 控制台的勾選 | Excel「介入」欄標 `O` 的那幾條 |
| 花費 | 本次花費 | 接受將花費（回答後變「本次花費」） |

一樣**永遠列出全部的詳細動作**（編號與控制台一致），標了 `O` 的是黑字、**其餘淺灰色**。回答之後眉標右邊會多一顆「已接受」／「未接受」的標記，控制台收掉卡片之前參與者都看得到。

接受的步驟，步驟卡右邊會出現藍色的「🤖 主動」標記（與琥珀色的「🤖 介入」並存）。提議卡浮著的時候參與者一樣不能換頁，勾「完成」時會自動收掉。

## 參與者畫面

參與者**只能**換頁（上一步／下一步、方向鍵）、捲動步驟列表，以及滑鼠移入步驟預覽它的詳細步驟。**點擊步驟卡不會勾選、不會變灰、不會扣點** —— 這些一律由控制台決定。參與者換頁時控制台會同步跟著換。

### 接受幫助的說明卡
控制台勾「接受幫助」時，參與者畫面會浮出一張**蓋滿整個畫面**的卡片。最上面是「餐點 - 階段 - 步驟N」（Excel 沒填餐點的頁面就只有「階段 - 步驟N」）與步驟名稱，中間是詳細步驟，最下面是圖例與本次花費的點數。

詳細步驟**永遠列出全部**（編號因此與控制台上的完全一致），用顏色區分誰做：

| 控制台 | 說明卡 | 意思 |
|---|---|---|
| 有勾 | 黑色字 | 助手會介入做這一條 |
| 沒勾 | 淺灰色字 | 參與者自己做 |

卡片最下方的「黑色字體動作將由助手介入、淺灰色字體則由您獨立完成」**只在真的有灰字時才出現**；整個步驟全部由助手做的時候沒有東西要對照，就不顯示。那兩個詞本身用的正是清單上的兩種顏色。

詳細步驟**直向排成一欄**；一欄放不下（會需要捲動）時才自動改成兩欄、三欄，多欄時一樣是先看完左邊那一欄再看右邊。最多幾欄由 `client/client.js` 開頭的 `MAX_HELP_COLUMNS` 決定；超過三欄還放不下才會出現捲軸。

卡片出現期間**不能換頁**（上一步／下一步與方向鍵都不作用），要參與者先看完。參與者自己關不掉，由控制台收：勾「完成」會自動關閉，或按控制台上的「隱藏說明卡 / 關閉說明卡」。狀態在 server，所以參與者畫面重新整理後卡片還在。

### 現在該做的那一步
顏色高亮（底色＋左側直條）永遠固定在**本頁還沒完成、編號最小**的那個步驟，滑鼠移入不會改變它。控制台每勾掉一個「完成」，高亮就自動往下移一格；整頁都完成時不再高亮。

### 滑鼠移入
移入某個步驟時，左下角的「詳細步驟」會切成該步驟的內容，卡片本身只會向右輕推一點並換個邊框顏色（`--card-hover-bg` / `--card-hover-border`）—— **不會有左側直條，也不會變成高亮的樣子**。滑鼠離開列表後，詳細步驟自動切回「現在該做的那一步」。

### 自動捲動
步驟列表會自動捲動，讓「現在該做的那一步」上方**最多只留兩個已完成的步驟**。要改這個數字，修改 `client/client.js` 開頭的 `MAX_DONE_ABOVE`。只有在「該做的那一步」真的換人時才會捲動，單純調整點數不會把畫面拉走；參與者仍可自己捲動或用 `▼` 按鈕，Wizard 則可透過「在 Client 顯示」指定查看位置。

### 上方的三張卡

由左到右：

1. **階段**：目前的「餐點 階段」（Excel 中餐點為 `-` 時只顯示階段）與該階段的圖示，見下面的「階段圖示」。
2. **花費**（兩行）：
   - **此步驟剩餘動作所需花費點數** —— 目前這一頁裡還沒被勾「完成」的動作，點數加總。
   - **實驗剩餘動作所需花費點數** —— 整份食譜裡還沒被勾「完成」的動作，點數加總。
3. **點數**（兩行）：
   - **剩餘可指揮助手點數** —— 參與者自己還能指揮助手多少點（＝總點數 ＋ 這一池的帳本總和）。
   - **剩餘主動幫助點數** —— 助手主動提議的額度還剩多少（見〈助手主動提議〉）。這一行可以整行關掉，見 `client/client.js` 的 `SHOW_PROACTIVE_POINTS`。

前兩個都只算**還沒完成**的動作，所以控制台每勾一個「完成」就會跟著往下掉。「實驗剩餘」算的是全部頁面、不看目前在第幾頁 —— 這樣翻頁不會讓數字忽上忽下，只有真的完成動作才會減少。

其他進度資訊：

- **最下方進度條右側**：目前頁數 / 總頁數。
- **右側步驟列表**：可捲動時上下出現漸層遮罩，下方還有步驟時出現 `▼` 按鈕。

點擊上方資訊區右側的「全螢幕」進入全螢幕；按 `Esc` 離開。版面固定在一個螢幕內，內容過長時會在任務列表或詳細步驟區內捲動。

若 server 沒開或斷線，兩個畫面下方都會出現紅色提示；server 重開後會自動恢復連線與狀態。

## 更新 Excel 資料

Excel 有修改時執行：

```sh
python3 scripts/extract_recipe.py
```

程式會從 `data/User Study v3.xlsx` 的「食譜excel v2」讀取資料，並重新產生 `data/recipe-data.js`，不會修改 Excel。每當「餐點」或「階段」欄出現值時會建立新的一頁；「種類」欄不會匯入。**M 欄「介入」**標 `O` 的詳細動作會被記成主動提議的範圍（見〈助手主動提議〉）；沒有這一欄也能跑，只是整份食譜都沒有主動幫助。

> 「介入」欄的 `O` 記的是**詳細動作的索引**，所以那一列的「步驟內容」必須有文字 —— 標了 `O` 卻沒填內容的列會被略過（不會讓後面的編號整排位移）。執行後印出的主動幫助表格可以確認每個步驟標到幾條。

**「餐點」與「階段」都是 `-` 的頁面不會進食譜**（空白也算），兩個 UI 都看不到它。這種頁面沒有任何身分可以顯示給參與者看，留著只會多一頁空白。執行時會印出被略過的是哪一頁，例如：

```
略過原第 22 頁：餐點與階段都是「-」—— 將使用過的鍋子、食物夾 放進水槽、洗鍋子
```

被略過之後頁碼會重新排成連號。**如果被略過的不是最後一頁，後面所有頁的頁碼都會往前移一格** —— 這時要順便檢查 `images/steps/` 的檔名（檔名是照頁碼取的，見下面的「步驟圖片」）。

執行完成後也會以表格列出各個「餐點－階段」的總花費。若環境有安裝 `prettytable` 會自動使用；未安裝時會使用腳本內建的等寬表格，不影響資料產生。

改完資料後要**重啟 server**（頁數與原價是在啟動時讀進來的）。

> 同理，改完 `server/*.py` 也一定要重啟 server —— Python 不會自動重載。若送出的動作被忽略（按鈕沒反應），server 的終端機會印出 `[warn] 未知的 action`，那就是還沒重啟。改 HTML / CSS / JS 則不用重啟，重新整理瀏覽器即可。

## 階段圖示

最上方左邊那張卡的圖示。**不需要改任何程式碼**，把檔案照下面的規則命名後丟進 `images/icon/` 即可。

### 檔名要怎麼取

檔名就是**畫面上那張卡顯示的文字**，三種寫法擇一：

| 檔名 | 套用範圍 | 例子 |
|---|---|---|
| `<餐點>-<階段>` | 該「餐點 階段」的**每一頁** | `images/icon/巴斯克蛋糕-製作.jpeg` |
| `<階段>` | 該階段的每一頁，**不分餐點** | `images/icon/整理清潔.jpeg` |
| `<頁碼>` | 只有那一頁 | `images/icon/4.jpeg` |

- 餐點與階段要跟 Excel 裡的字**完全一樣**，中間用一個半形 `-` 連起來。
- Excel 中餐點是 `-` 的頁面（例如「拿用具」「整理清潔」）沒有餐點，直接用階段當檔名。
- 副檔名 `.jpeg` `.jpg` `.png` `.webp` `.gif` `.avif` 都可以，**混用也沒關係**（比對只看檔名，不看副檔名）。
- 找不到就不顯示圖，那張卡只留階段名稱。

目前的 21 頁需要這些檔名（一個檔案就蓋掉該階段的所有頁面）：

```
images/icon/拿用具.jpeg
images/icon/整理清潔.jpeg              ← 第 5、9、16、21 頁共用
images/icon/巴斯克蛋糕-拿食材.jpeg
images/icon/巴斯克蛋糕-備料.jpeg
images/icon/巴斯克蛋糕-製作.jpeg        ← 第 4、10、17、20 頁共用
images/icon/法式吐司-拿食材.jpeg
images/icon/法式吐司-備料.jpeg
images/icon/法式吐司-製作.jpeg          ← 第 8、18、19 頁共用
images/icon/水果優格-拿食材.jpeg
images/icon/水果優格-備料.jpeg          ← 第 12、14 頁共用
images/icon/水果優格-製作.jpeg          ← 第 13、15 頁共用
```

### 比對順序

`頁碼` → `餐點-階段` → `階段`，**先找到的先用**。所以想讓某一頁用不一樣的圖，就多放一個以頁碼命名的檔案蓋過去。

三種都沒有時，最後才退回 `client/client.js` 的 `MEAL_ICONS`（用餐點名稱的關鍵字比對）。**目前是空的**，也就是沒有退路：`images/icon/` 裡找不到就不顯示圖。要加回來的話照註解裡的格式寫。

**加了圖片重整瀏覽器即可，不用重啟 server** —— 每次載入頁面都會重新掃描 `images/icon/`。

### 圖示的大小

圖片**維持原比例**縮到剛好放得下（`object-fit: contain`），不會變形也不會裁切。所以實際大小是由「版位」決定的，版位有兩個限制：

- **高度**：`--meal-icon-height` 預設 `auto` ＝ 吃滿整張卡（扣掉上下內距）。**這通常才是真正的限制** —— 想讓圖更大，多半要調高上方區塊本身，也就是 `--top-panel-height`（螢幕高度 ≤760px 時是 `--top-panel-height-compact`）。
- **寬度**：`--meal-icon-width` 是上限，預設 `clamp(120px, 14vw, 260px)`。橫幅的圖才會卡在這裡。

整張卡的寬度是 `--step-panel-width`（預設 `.95fr`）。它和 `--cost-panel-width`、`--points-panel-width` 是同一組比例值，調小一個、其他就會分到更多空間。卡片裡「餐點」與「階段」各佔一行，剩下的寬度全部給圖示。

## 說明卡的字級

卡片上每一塊文字各自一個變數，全部在 `client/client.css` 最上方的變數區，**由上到下**照著卡片的順序排：

```
┌────────────────────────────────────────────┐
│  🤖 助手介入 │ 巴斯克蛋糕 - 製作 - 步驟8       │ 標題列（深奶油色底）
│  └ --help-card-badge-size                   │
│               └ --help-card-step-size       │
├────────────────────────────────────────────┤
│  準備4個金屬蛋糕模，將紙模分別放入其中           │ --help-card-title-size
├────────────────────────────────────────────┤
│  01  拿金屬蛋糕模1                            │ 編號 --help-card-index-size
│  02  金屬蛋糕模1 放到工作區                    │ 文字 --help-card-item-size
│  …                                          │
├────────────────────────────────────────────┤
│  黑色字體動作將…    本次花費  13 點             │
│  └ --help-card-legend-size                  │
│                    └ --help-card-cost-label-size
│                              └ --help-card-cost-size
│                                 └ --help-card-cost-unit-size
└────────────────────────────────────────────┘
```

| 卡片上的位置 | 變數 | 預設 |
|---|---|---|
| 標題列的「🤖 助手介入」 | `--help-card-badge-size` | `1.5rem` |
| 標題列右邊的「餐點 - 階段 - 步驟N」 | `--help-card-step-size` | `1.5rem` |
| 步驟名稱（最大那行） | `--help-card-title-size` | `2.4rem` |
| 詳細步驟前面的編號 `01` | `--help-card-index-size` | `.78em` |
| 詳細步驟的文字 | `--help-card-item-size` | `1.7rem` |
| 最下方的圖例 | `--help-card-legend-size` | `1.2rem` |
| 「本次花費」四個字 | `--help-card-cost-label-size` | `1.7rem` |
| 點數的數字 | `--help-card-cost-size` | `3.6rem` |
| 數字後面的「點」 | `--help-card-cost-unit-size` | `.4em` |

**單位是 `rem` 的可以自己設定大小；單位是 `em` 的（編號、「點」）是相對值** —— `.78em` 代表「旁邊那行文字的 78%」，所以調大 `--help-card-item-size` 時編號會自己跟著變大，不用兩個一起改。想讓它們不要連動就改成 `rem`。

螢幕高度不超過 760px 時，檔案最下方的 `@media (max-height: 760px)` 會整組換成小一號的值，那邊也要一起改。

整張卡**只有兩個色塊**：奶油色的標頭（`--helped-bg`）與其餘的白色，中間各用一條 `--line` 的細線分隔。標題行不另外給底色，靠琥珀色（`--helped-badge-text`）與較小的字級當「眉標」，跟底下黑色的步驟名稱分開。

其他顏色：

- 「參與者自己做」那幾條的淺灰色：`--help-card-off-text`（預設 `#b4b7ae`）。
- 卡片外框與標題列文字：沿用「接受幫助」那組 `--helped-*`，見最下面的「調整全部顏色」。
- 背後的遮罩：`--overlay-scrim`。

排版相關：詳細步驟最多分成幾欄由 `client/client.js` 開頭的 `MAX_HELP_COLUMNS` 決定（預設 `3`）。

## 步驟圖片

每個步驟都可以有自己的圖片，顯示在參與者畫面左上角。**不需要改任何程式碼**，只要把檔案照規則命名後丟進 `images/steps/`。

### 命名規則

```
images/steps/<頁>-<步驟>.<副檔名>
```

- `images/steps/3-2.jpg` ＝ **第 3 頁**的**第 2 個步驟**（就是畫面上編號 `2.` 的那張卡）。
- 兩個數字都是畫面上看得到的編號，從 1 開始算，跟 Wizard 控制台顯示的一致。
- 可以補零，`03-02.jpg` 與 `3-2.jpg` 效果相同（補零在 Finder 裡比較好排序，建議用）。
- 分隔符號用 `-` 或 `_` 都可以。
- 只寫頁數的 `images/steps/3.jpg` 是**整頁的預設圖**，該頁沒有專屬圖的步驟都會用它。
- 支援 `.jpg` `.jpeg` `.png` `.webp` `.gif` `.avif`。
- 檔名不符規則的檔案（例如 `note.png`）會直接被忽略，可以安心放在同一個資料夾。

### 顯示規則

| 情況 | 顯示 |
|---|---|
| 該步驟有專屬圖 | 用專屬圖 |
| 沒有專屬圖，但該頁有預設圖 | 用該頁的預設圖 |
| 都沒有 | 顯示原本的預留版位 |

參與者滑鼠移入某個步驟時，圖片會跟著詳細步驟一起換成該步驟的圖；滑鼠離開後回到「現在該做的那一步」。

### 加了圖片之後

**重整瀏覽器即可，不用重啟 server** —— 每次載入頁面都會重新掃描 `images/steps/`。

在 Wizard 控制台的步驟清單上，有圖片的步驟會顯示 🖼 記號（`🖼·頁` 代表用的是整頁的預設圖，沒有專屬圖），滑鼠移上去可以看到實際的檔案路徑。用這個確認檔名有沒有放對。

### 例外設定

少數需要指到 `images/steps/` 以外的檔案時，才在 `client/client.js` 開頭的 `STEP_IMAGES` 寫，key 的寫法一樣，會蓋過掃描到的檔案：

```js
const STEP_IMAGES = {
  "3-2": "/images/special/whisk.jpg",  // 第 3 頁第 2 個步驟
  "5": "/images/clean.jpg",            // 第 5 頁的預設圖
};
```

> 路徑一律用開頭有 `/` 的絕對路徑。

### 圖片比例與版位

預設是 `object-fit: contain`，也就是**完整顯示整張圖、絕對不裁切**，圖片比例和版位不合時會在兩側留空白。兩個變數在 `client/client.css` 開頭：

- `--preview-image-height`（預設 `50%`）：圖片版位佔左側面板的高度比例，剩下的給「詳細步驟」。**兩側空白太多就把它調大**，一路調到圖片剛好填滿寬度為止（1280×960 這種 4:3 的圖大約要 `65%`～`70%`）。調太大則「詳細步驟」會被壓縮，不過那一區本身可以捲動，不會有東西看不到。
- `--step-image-fit`（預設 `contain`）：改成 `cover` 會填滿整個版位，但超出的部分會被裁掉（上下或左右）。只有在你的圖片都已經裁成同一個比例、想要滿版時才用。

所有圖片建議統一成同一個比例，這樣調好一次就全部合適。

## 調整全部顏色

參與者畫面的顏色集中在 `client/client.css` 最上方的「全站色彩」區；控制台的在 `wizard/wizard.css` 最上方。修改該區的變數即可，不需要搜尋下方的 CSS 規則。

### 現在該做的那一步

本頁還沒完成、編號最小的步驟。位置由程式決定，滑鼠移入不會改變。

- `--active-bg`：底色（想更明顯就調深）。
- `--active-border`：外框顏色。
- `--active-bar`：左側直條色。
- `--active-ink`：步驟名稱文字色。
- `--active-shadow`：外陰影。
- 只有滑鼠經過的卡片用 `--card-hover-bg` 與 `--card-hover-border`，與上面的 `--active-*` 是分開的。

### 已完成的步驟

被勾選「完成」的步驟整張卡（含點數標籤與已介入標記）會轉成灰階，不會另外加勾勾：

- `--done-grayscale`：灰階強度，`1` 是全灰、`0` 是不變灰。
- `--done-opacity`：淡化程度，數字越小越淡。

### 接受幫助的步驟

步驟卡最右邊會出現「🤖 已介入」標記（在點數標籤的後面）。

- `--helped-border`：外框顏色。
- `--helped-bg`：底色。
- `--helped-badge-bg` / `--helped-badge-text`：「🤖 已介入」標記的底色與文字色。

同一組顏色也用在整頁的說明卡上（外框、標頭底色、編號）。

### 助手主動提議的步驟

接受主動提議的步驟，卡片最右邊會出現藍色的「🤖 主動」標記（與琥珀色的「🤖 介入」並存）。兩個檔案裡都有同一組變數：

- `--proactive-border`：外框顏色（也是提議卡的外框、控制台步驟列左緣的直條）。
- `--proactive-bg`：底色（也是提議卡的標頭底色）。
- `--proactive-text`：文字色。
- 參與者畫面另外有 `--proactive-badge-bg`（標記底色）與 `--proactive-accepted-*` / `--proactive-declined-*`（提議卡上「已接受」／「未接受」標記的顏色）。

標記文字要改的話，修改 `client/client.js` 的 `syncHelpBadges()`；兩張卡上的「🤖 助手介入」「🤖 助手主動提議」等文字在 `client/client.js` 的 `syncHelpOverlay()` 裡（版面在 `client/index.html` 的 `#help-overlay` 區塊）。

# WoZ 實驗系統

參與者看的食譜畫面（client）＋ 實驗者操控的控制台（wizard），兩邊透過一個 Python server 即時同步。

## 啟動

```sh
python3 server/serve.py
```

只用 Python 標準函式庫，不需要安裝任何套件。啟動後會印出兩組網址：

```
本機      http://localhost:8000
區網      http://192.168.x.x:8000
參與者    http://localhost:8000/client/
Wizard    http://localhost:8000/wizard/
```

開 `http://localhost:8000` 會看到啟動頁，兩個連結分別進入參與者畫面與控制台。

- **同一台電腦**：開兩個瀏覽器視窗，一個放參與者畫面（拖到外接螢幕後按「全螢幕」），一個放控制台。
- **兩台電腦**：另一台連區網網址（例如 `http://192.168.0.12:8000/client/`），兩台要在同一個區域網路下。程式碼路徑完全相同，不用改任何設定。

其他選項：`--port 8000`、`--host 0.0.0.0`（預設綁全部介面，跨機才連得到）。

> 必須透過這個 server 開啟，不能用 `file://` 直接開 HTML。

## 目錄結構

```
server/serve.py     靜態檔案 + /api 狀態中繼（SSE 推送 / POST 動作）
server/state.py     預設狀態與 reducer —— 所有規則只在這裡實作一次
shared/store.js     前端連線層：訂閱狀態、送出動作
shared/format.js    兩邊共用的格式化工具
client/             參與者畫面
wizard/             Wizard 控制台
data/               Excel 與產生出來的 recipe-data.js
sessions/           每次啟動自動產生的操作紀錄（JSONL）
scripts/            Excel → recipe-data.js 的轉換腳本
```

**狀態放在 server，兩個 UI 都只送「動作」**。任何一邊按下按鈕，送出的是意圖（例如「把 0:1 標成接受幫助、花費 3 點」），server 套用規則、算出新狀態，再推播給所有連著的畫面。因此兩邊不可能不同步，重新整理也不會掉狀態。

## Wizard 控制台

### 上方：頁面切換
每一頁一顆數字按鈕，直接跳頁，或用左右箭頭。右上角小圓點代表那一頁已經有勾選紀錄。右側顯示目前的「餐點 · 階段」與連線狀態。

### 左下：本頁步驟
每個步驟兩個勾選框：

- **完成** —— 參與者畫面上該步驟轉成灰階（代表參與者已經做完，不用再看）。**不影響點數。**
- **接受幫助** —— 參與者畫面上該步驟會出現「🤖 已介入」標記、浮出一張整頁的**說明卡**（見下一節），同時依照旁邊「花費」欄位的數字扣點。勾選後花費欄位會鎖住，要改金額就改詳細步驟，或先取消勾選。

「本頁全部完成 / 本頁全部取消」可以一次處理整頁。

#### 詳細步驟與計價
每個步驟底下的「詳細步驟 N / N」展開後，是這個步驟在 Excel 上的分解動作，**預設全部勾選**。這份勾選同時決定兩件事：

- 參與者說明卡上哪幾條是黑的 —— 說明卡**永遠列出全部的動作**，勾起來的是黑字（助手會做），**沒勾的變成淺灰色**（參與者自己做）。
- 花費多少點 —— **全部勾選＝Excel 原價；少勾幾個＝剩下勾選的個數**（目前資料裡每個步驟的原價都剛好等於詳細步驟的個數，所以兩條規則是同一條）。

勾「接受幫助」時該步驟會自動展開，方便馬上調整。已經扣過點之後再改詳細步驟也可以，**帳本上那一筆會就地改成新的金額，不會多記一筆**。

「花費」欄位平常跟著詳細步驟自動算；如果你手動打了數字，就以你打的為準，直到你再動一次詳細步驟為止（那時會交還給自動計價）。要記任意金額也可以用右側的「手動調整」。

#### 說明卡的開關
每個步驟右邊的「顯示說明卡 / 隱藏說明卡」控制參與者畫面上那張整頁的框。勾「接受幫助」時會自動叫出來，勾「完成」時會自動收掉。說明卡屬於哪一頁的步驟都沒關係 —— 只要有卡在顯示，步驟清單上方就會出現一條提示列，上面的「關閉說明卡」隨時關得掉。

**「↕ 捲回目前步驟」**：參與者自己把列表捲走之後，用這顆把他的畫面捲回定位（現在該做的那一步上方最多兩個已完成步驟）。這顆按鈕不會改動任何實驗資料，也不會寫進點數紀錄。

### 右下：點數
- **總點數**：參與者的預算（預設 100）。要改預設值請修改 `server/state.py` 的 `TOTAL_POINTS`。
- **剩餘點數**：永遠等於 `總點數 + 所有帳目的總和`，沒有第二個來源。負數會顯示成紅色。
- **手動調整**：輸入數字後按「＋ 加點」或「－ 扣點」（按 Enter 等於扣點）。
- **紀錄**：每一筆點數變動都在這裡，顯示時間、來源、增減金額與當下餘額，最新的在最上面。
- **回溯上一筆**：撤銷最後一筆帳目，可以連續按。如果撤銷的是「接受幫助」，參與者畫面上對應的標記也會跟著消失。
- **重置全部**：清空頁面、勾選與所有點數紀錄，換受試者時用。

### 帳本的規則
帳本是「目前生效的帳目清單」，不是唯讀的歷史日誌 —— **取消勾選「接受幫助」時，那一筆帳目會直接消失、點數自動回補**，而不是再記一筆反向帳。同理，**改詳細步驟是就地改掉那一筆的金額**，不會多一筆。這樣「剩餘點數」與畫面上的勾選狀態不可能脫鉤，回溯的結果也永遠可預期。

沒有全勾詳細步驟的帳目，紀錄上會標成「第3頁 · 步驟02 接受幫助（5/7 動作）」，事後看紀錄一眼就知道為什麼不是原價。

完整、不可竄改的操作歷程另外記在 `sessions/session-YYYYMMDD-HHMMSS.jsonl`，每個動作一行，實驗結束後可直接拿來分析。

## 參與者畫面

參與者**只能**換頁（上一步／下一步、方向鍵）、捲動步驟列表，以及滑鼠移入步驟預覽它的詳細步驟。**點擊步驟卡不會勾選、不會變灰、不會扣點** —— 這些一律由控制台決定。參與者換頁時控制台會同步跟著換。

### 接受幫助的說明卡
控制台勾「接受幫助」時，參與者畫面會浮出一張**蓋滿整個畫面**的卡片。最上面是「餐點 - 階段 - 步驟N」（Excel 沒填餐點的頁面就只有「階段 - 步驟N」）與步驟名稱，中間是詳細步驟，最下面是圖例與本次花費的點數。

詳細步驟**永遠列出全部**（編號因此與控制台上的完全一致），用顏色區分誰做：

| 控制台 | 說明卡 | 意思 |
|---|---|---|
| 有勾 | 黑色字 | 助手會介入做這一條 |
| 沒勾 | 淺灰色字 | 參與者自己做 |

卡片最下方的「黑色字體動作將由助手介入、淺灰色字體則由您獨立完成」**只在真的有灰字時才出現**；整個步驟全部由助手做的時候沒有東西要對照，就不顯示。那兩個詞本身用的正是清單上的兩種顏色。

詳細步驟**直向排成一欄**；一欄放不下（會需要捲動）時才自動改成兩欄、三欄，多欄時一樣是先看完左邊那一欄再看右邊。最多幾欄由 `client/client.js` 開頭的 `MAX_HELP_COLUMNS` 決定；超過三欄還放不下才會出現捲軸。

卡片出現期間**不能換頁**（上一步／下一步與方向鍵都不作用），要參與者先看完。參與者自己關不掉，由控制台收：勾「完成」會自動關閉，或按控制台上的「隱藏說明卡 / 關閉說明卡」。狀態在 server，所以參與者畫面重新整理後卡片還在。

### 現在該做的那一步
顏色高亮（底色＋左側直條）永遠固定在**本頁還沒完成、編號最小**的那個步驟，滑鼠移入不會改變它。控制台每勾掉一個「完成」，高亮就自動往下移一格；整頁都完成時不再高亮。

### 滑鼠移入
移入某個步驟時，左下角的「詳細步驟」會切成該步驟的內容，卡片本身只會向右輕推一點並換個邊框顏色（`--card-hover-bg` / `--card-hover-border`）—— **不會有左側直條，也不會變成高亮的樣子**。滑鼠離開列表後，詳細步驟自動切回「現在該做的那一步」。

### 自動捲動
步驟列表會自動捲動，讓「現在該做的那一步」上方**最多只留兩個已完成的步驟**。要改這個數字，修改 `client/client.js` 開頭的 `MAX_DONE_ABOVE`。只有在「該做的那一步」真的換人時才會捲動，單純調整點數不會把畫面拉走；參與者仍可自己捲動或用 `▼` 按鈕，控制台的「↕ 捲回目前步驟」可以隨時把畫面捲回定位。

畫面上的三個進度資訊：

- **右上角資訊卡**：目前的「餐點 階段」（Excel 中餐點為 `-` 時只顯示階段），下方是「本階段已完成步驟 / 本階段步驟總數」，數字來自控制台勾選的「完成」。
- **最下方進度條右側**：目前頁數 / 總頁數。
- **右側步驟列表**：可捲動時上下出現漸層遮罩，下方還有步驟時出現 `▼` 按鈕。

點擊上方資訊區右側的「全螢幕」進入全螢幕；按 `Esc` 離開。版面固定在一個螢幕內，內容過長時會在任務列表或詳細步驟區內捲動。

若 server 沒開或斷線，兩個畫面下方都會出現紅色提示；server 重開後會自動恢復連線與狀態。

## 更新 Excel 資料

Excel 有修改時執行：

```sh
python3 scripts/extract_recipe.py
```

程式會從 `data/User Study v3.xlsx` 的「食譜excel v2」讀取資料，並重新產生 `data/recipe-data.js`，不會修改 Excel。每當「餐點」或「階段」欄出現值時會建立新的一頁；「種類」欄不會匯入。

**「餐點」與「階段」都是 `-` 的頁面不會進食譜**（空白也算），兩個 UI 都看不到它。這種頁面沒有任何身分可以顯示給參與者看，留著只會多一頁空白。執行時會印出被略過的是哪一頁，例如：

```
略過原第 22 頁：餐點與階段都是「-」—— 將使用過的鍋子、食物夾 放進水槽、洗鍋子
```

被略過之後頁碼會重新排成連號。**如果被略過的不是最後一頁，後面所有頁的頁碼都會往前移一格** —— 這時要順便檢查 `images/steps/` 的檔名（檔名是照頁碼取的，見下面的「步驟圖片」）。

執行完成後也會以表格列出各個「餐點－階段」的總花費。若環境有安裝 `prettytable` 會自動使用；未安裝時會使用腳本內建的等寬表格，不影響資料產生。

改完資料後要**重啟 server**（頁數與原價是在啟動時讀進來的）。

> 同理，改完 `server/*.py` 也一定要重啟 server —— Python 不會自動重載。若送出的動作被忽略（按鈕沒反應），server 的終端機會印出 `[warn] 未知的 action`，那就是還沒重啟。改 HTML / CSS / JS 則不用重啟，重新整理瀏覽器即可。

## 調整點數與圖片

- 總點數：修改 `server/state.py` 的 `TOTAL_POINTS`。
- 上方區塊高度：修改 `client/client.css` 開頭的 `--top-panel-height`；螢幕高度不超過 760px 時使用 `--top-panel-height-compact`。
- 全螢幕按鈕區寬度：修改 `--fullscreen-width`。
- 上方「剩餘步驟花費」寬度：修改 `--cost-panel-width`。
- 上方「剩餘點數」寬度：修改 `--points-panel-width`。
- 上方「階段進度＋圖片」寬度：修改 `--step-panel-width`。
- 上方區塊左側標題：修改 `--stat-label-size`。
- 上方區塊右側數字：修改 `--stat-value-size`。
- 上方數字旁的「點」與階段步驟總數：修改 `--stat-unit-size`。
- 上方步驟卡的餐點名稱：修改 `--meal-label-size`。
- 上方步驟卡的階段名稱：修改 `--stage-name-size`（與餐點名稱同一行，建議設成一樣大）。
- 上方步驟卡的「本階段已完成步驟」小字：修改 `--stage-hint-size`。
- 最下方進度條旁的頁數：修改 `--progress-count-size`。
- 右側步驟名稱：修改 `--step-name-size`。
- 步驟卡最左側編號：修改 `--step-index-size`。
- 點數標籤：修改 `--cost-size`。
- 步驟卡之間的距離：修改 `--action-gap`。
- 詳細步驟標題：修改 `--detail-title-size`。
- 詳細步驟內文：修改 `--detail-text-size`。
- 詳細步驟最多分成幾欄：修改 `client/client.js` 開頭的 `MAX_DETAIL_COLUMNS`（預設 `2`）。平常是直的一欄，放不下才會變成兩欄並平均分配。
- 詳細步驟上下／左右間距：修改 `--detail-row-gap` 與 `--detail-column-gap`。
- 說明卡的字級與顏色：見下面的「說明卡的字級」。
- 步驟圖片：見下面的「步驟圖片」章節。

最上方「步驟」資訊卡右側的餐點圖示依 `client/client.js` 中的 `MEAL_ICONS` 自動判斷，目前使用：

- 巴斯克蛋糕：`/images/icon/cake.png`
- 吐司：`/images/icon/toast.png`
- 優格：`/images/icon/yogurt.png`

圖示寬度與高度可修改 `client/client.css` 開頭的 `--meal-icon-width` 和 `--meal-icon-height`；螢幕高度不超過 760px 時使用 `--meal-icon-height-compact`。

## 說明卡的字級

卡片上每一塊文字各自一個變數，全部在 `client/client.css` 最上方的變數區，**由上到下**照著卡片的順序排：

```
┌────────────────────────────────────────────┐
│  🤖 助手介入 │ 巴斯克蛋糕 - 製作 - 步驟8       │ 標題列（深奶油色底）
│  └ --help-card-badge-size                   │
│               └ --help-card-step-size       │
├────────────────────────────────────────────┤
│  準備4個金屬蛋糕模，將紙模分別放入其中           │ --help-card-title-size
├────────────────────────────────────────────┤
│  01  拿金屬蛋糕模1                            │ 編號 --help-card-index-size
│  02  金屬蛋糕模1 放到工作區                    │ 文字 --help-card-item-size
│  …                                          │
├────────────────────────────────────────────┤
│  黑色字體動作將…    本次花費  13 點             │
│  └ --help-card-legend-size                  │
│                    └ --help-card-cost-label-size
│                              └ --help-card-cost-size
│                                 └ --help-card-cost-unit-size
└────────────────────────────────────────────┘
```

| 卡片上的位置 | 變數 | 預設 |
|---|---|---|
| 標題列的「🤖 助手介入」 | `--help-card-badge-size` | `1.5rem` |
| 標題列右邊的「餐點 - 階段 - 步驟N」 | `--help-card-step-size` | `1.5rem` |
| 步驟名稱（最大那行） | `--help-card-title-size` | `2.4rem` |
| 詳細步驟前面的編號 `01` | `--help-card-index-size` | `.78em` |
| 詳細步驟的文字 | `--help-card-item-size` | `1.7rem` |
| 最下方的圖例 | `--help-card-legend-size` | `1.2rem` |
| 「本次花費」四個字 | `--help-card-cost-label-size` | `1.7rem` |
| 點數的數字 | `--help-card-cost-size` | `3.6rem` |
| 數字後面的「點」 | `--help-card-cost-unit-size` | `.4em` |

**單位是 `rem` 的可以自己設定大小；單位是 `em` 的（編號、「點」）是相對值** —— `.78em` 代表「旁邊那行文字的 78%」，所以調大 `--help-card-item-size` 時編號會自己跟著變大，不用兩個一起改。想讓它們不要連動就改成 `rem`。

螢幕高度不超過 760px 時，檔案最下方的 `@media (max-height: 760px)` 會整組換成小一號的值，那邊也要一起改。

整張卡**只有兩個色塊**：奶油色的標頭（`--helped-bg`）與其餘的白色，中間各用一條 `--line` 的細線分隔。標題行不另外給底色，靠琥珀色（`--helped-badge-text`）與較小的字級當「眉標」，跟底下黑色的步驟名稱分開。

其他顏色：

- 「參與者自己做」那幾條的淺灰色：`--help-card-off-text`（預設 `#b4b7ae`）。
- 卡片外框與標題列文字：沿用「接受幫助」那組 `--helped-*`，見最下面的「調整全部顏色」。
- 背後的遮罩：`--overlay-scrim`。

排版相關：詳細步驟最多分成幾欄由 `client/client.js` 開頭的 `MAX_HELP_COLUMNS` 決定（預設 `3`）。

## 步驟圖片

每個步驟都可以有自己的圖片，顯示在參與者畫面左上角。**不需要改任何程式碼**，只要把檔案照規則命名後丟進 `images/steps/`。

### 命名規則

```
images/steps/<頁>-<步驟>.<副檔名>
```

- `images/steps/3-2.jpg` ＝ **第 3 頁**的**第 2 個步驟**（就是畫面上編號 `2.` 的那張卡）。
- 兩個數字都是畫面上看得到的編號，從 1 開始算，跟 Wizard 控制台顯示的一致。
- 可以補零，`03-02.jpg` 與 `3-2.jpg` 效果相同（補零在 Finder 裡比較好排序，建議用）。
- 分隔符號用 `-` 或 `_` 都可以。
- 只寫頁數的 `images/steps/3.jpg` 是**整頁的預設圖**，該頁沒有專屬圖的步驟都會用它。
- 支援 `.jpg` `.jpeg` `.png` `.webp` `.gif` `.avif`。
- 檔名不符規則的檔案（例如 `note.png`）會直接被忽略，可以安心放在同一個資料夾。

### 顯示規則

| 情況 | 顯示 |
|---|---|
| 該步驟有專屬圖 | 用專屬圖 |
| 沒有專屬圖，但該頁有預設圖 | 用該頁的預設圖 |
| 都沒有 | 顯示原本的預留版位 |

參與者滑鼠移入某個步驟時，圖片會跟著詳細步驟一起換成該步驟的圖；滑鼠離開後回到「現在該做的那一步」。

### 加了圖片之後

**重整瀏覽器即可，不用重啟 server** —— 每次載入頁面都會重新掃描 `images/steps/`。

在 Wizard 控制台的步驟清單上，有圖片的步驟會顯示 🖼 記號（`🖼·頁` 代表用的是整頁的預設圖，沒有專屬圖），滑鼠移上去可以看到實際的檔案路徑。用這個確認檔名有沒有放對。

### 例外設定

少數需要指到 `images/steps/` 以外的檔案時，才在 `client/client.js` 開頭的 `STEP_IMAGES` 寫，key 的寫法一樣，會蓋過掃描到的檔案：

```js
const STEP_IMAGES = {
  "3-2": "/images/special/whisk.jpg",  // 第 3 頁第 2 個步驟
  "5": "/images/clean.jpg",            // 第 5 頁的預設圖
};
```

> 路徑一律用開頭有 `/` 的絕對路徑。

### 圖片比例與版位

預設是 `object-fit: contain`，也就是**完整顯示整張圖、絕對不裁切**，圖片比例和版位不合時會在兩側留空白。兩個變數在 `client/client.css` 開頭：

- `--preview-image-height`（預設 `50%`）：圖片版位佔左側面板的高度比例，剩下的給「詳細步驟」。**兩側空白太多就把它調大**，一路調到圖片剛好填滿寬度為止（1280×960 這種 4:3 的圖大約要 `65%`～`70%`）。調太大則「詳細步驟」會被壓縮，不過那一區本身可以捲動，不會有東西看不到。
- `--step-image-fit`（預設 `contain`）：改成 `cover` 會填滿整個版位，但超出的部分會被裁掉（上下或左右）。只有在你的圖片都已經裁成同一個比例、想要滿版時才用。

所有圖片建議統一成同一個比例，這樣調好一次就全部合適。

## 調整全部顏色

參與者畫面的顏色集中在 `client/client.css` 最上方的「全站色彩」區；控制台的在 `wizard/wizard.css` 最上方。修改該區的變數即可，不需要搜尋下方的 CSS 規則。

### 現在該做的那一步

本頁還沒完成、編號最小的步驟。位置由程式決定，滑鼠移入不會改變。

- `--active-bg`：底色（想更明顯就調深）。
- `--active-border`：外框顏色。
- `--active-bar`：左側直條色。
- `--active-ink`：步驟名稱文字色。
- `--active-shadow`：外陰影。
- 只有滑鼠經過的卡片用 `--card-hover-bg` 與 `--card-hover-border`，與上面的 `--active-*` 是分開的。

### 已完成的步驟

被勾選「完成」的步驟整張卡（含點數標籤與已介入標記）會轉成灰階，不會另外加勾勾：

- `--done-grayscale`：灰階強度，`1` 是全灰、`0` 是不變灰。
- `--done-opacity`：淡化程度，數字越小越淡。

### 接受幫助的步驟

步驟卡最右邊會出現「🤖 已介入」標記（在點數標籤的後面）。

- `--helped-border`：外框顏色。
- `--helped-bg`：底色。
- `--helped-badge-bg` / `--helped-badge-text`：「🤖 已介入」標記的底色與文字色。

同一組顏色也用在整頁的說明卡上（外框、標頭底色、編號）。

標記文字要改的話，修改 `client/client.js` 的 `syncHelpBadge()`；說明卡上的「🤖 已為你完成」等文字在 `client/index.html` 的 `#help-overlay` 區塊裡。
